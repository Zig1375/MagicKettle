Magic Kettle 1.0.9: mod managers like r2modman can run with Steam, and the mods they install load.

## New in this version

- **A PowerShell you installed yourself is kept.** Magic Kettle only replaces Wine's placeholder or its own
  older stand-in, instead of overwriting another PowerShell during game preparation.
- **Cover downloads stop at 1 MB.** Oversized responses are cancelled while downloading, even when the server
  does not announce their size.

- **Known mod managers start without a graphics search.** SA Mod Manager and other recognized managers use one
  graphics backend, reusing the store’s running backend when possible. Explicit graphics choices are respected.

- **Deleting an entry whose files are already gone no longer offers to move them to the Trash.** The dialog only
  offers removal from Magic Kettle and explains that saves remain, without claiming the program is still on disk.

- **Cards with a missing program are readable even when their cached cover contains text.** A neutral background
  now separates the missing-file status and About button from the old artwork after an exe is moved or deleted.

- **Mod loaders next to a game's exe now load.** BepInEx (which r2modman and Thunderstore install) puts a small
  `winhttp.dll` next to the game, MelonLoader a `version.dll`, ASI loaders a `dinput8.dll`, and Windows loads the
  game's own copy first. Wine preferred its own built-in one, so the game started without any of its mods, with
  no error. Magic Kettle now lets the copy in the game's folder win for these three, as on Windows; a game without
  one still gets Wine's. This applies to every game, including Steam games started from a mod manager.
- **Mod managers work with Steam games by themselves: open r2modman's exe and use it as on Windows.** Tested
  start to finish with r2modman and Muck: opened from Downloads, r2modman installed BepInEx and Map Fix, and "Start
  modded" started Muck through Steam with both loaded. Four things made that work:
  - Magic Kettle knows mod managers (r2modman, Thunderstore Mod Manager, Gale, HedgeModManager, Vortex, the Nexus
    Mods app) by their exe and runs them beside the store's games from the first launch, in Steam's Windows (or
    Epic's when there is no Steam). In Windows of their own they found none of your games. Any other program can
    be put there by hand: right-click its card and choose "Run with Steam".
  - With both Steam and Epic installed, a mod manager asks at each launch which store's game you want to play
    with mods this time, with last time's store as the default button (Return repeats it). Each store has its
    own Windows, and a mod manager started beside Steam can't start an Epic game: HedgeModManager mods Sonic
    Frontiers from either store. It only asks when the manager works with both stores (all the known ones do)
    and both are installed. Right-click its card and turn off "Ask Which Store at Launch" to always use one.
  - SA Mod Manager (Sonic Adventure DX and 2) and Sonic Mania's mod manager are known too. Sonic Mania's sits in
    the game's own folder inside Steam's Windows: opening it there used to start Sonic Mania instead. It now gets
    a card of its own that runs with that store, and "Delete… › From disk" on it takes only its exe, never the
    game's folder.
  - A mod manager that comes with an installer (Vortex, the Nexus Mods app, Gale, r2modman's Setup) runs with
    the store too once it is installed. Before, it ran in a Windows of its own and found none of your games.
    Gale's card is also called "Gale" now, not after its installer's file name with the version in it.
  - When an installer starts its program on its last page ("Run Vortex"), Magic Kettle closes that copy and
    finishes the install by itself. Before, the install waited until you closed the program, and that copy ran
    without Magic Kettle's settings: Vortex showed a white window, the Nexus Mods app a black one. Start it from
    its card instead.
  - A mod manager gets the .NET its helper programs need, not only the .NET of its main program. Vortex runs
    its FOMOD installer on .NET 9 and stopped with "Vortex requires .NET Desktop Runtime 9".
  - Programs built with WPF draw their windows without the graphics card. SA Mod Manager's first window stayed
    white in Steam's Windows. If Steam was already running from an earlier version when you start such a
    program, quit Steam once so this applies.
  - Checked in Magic Kettle with each one's own download: r2modman 3.2.21, HedgeModManager 8.0 beta 7, Vortex
    2.10.1, the Nexus Mods app 0.21.1, SA Mod Manager 1.3.7 and ManiaModManager. Thunderstore Mod Manager runs
    on Overwolf, which isn't expected to work in Wine; r2modman, by the same author, does the same job.
  - A mod manager sees your displays as they are. Steam's Windows emulates the display for its games, so a game
    can switch resolution and a fixed-size window can be stretched; Vortex went transparent there once moved
    to a second monitor, and white when maximized. Programs run with a store are now left out of that, and the
    store's games keep it. If Steam was already running from an earlier version, quit it once so this applies.
  - Before such a program starts, Magic Kettle starts Steam in the background, the way it always starts it. A
    Steam started by r2modman itself checked its files, undid what Magic Kettle does to show its window, and hung
    without one, so the game never started.
  - Programs can ask Windows PowerShell for registry values again. Wine's PowerShell does nothing, and r2modman,
    which finds Steam that way, said "Unable to resolve steam install folder". Magic Kettle now puts a small
    PowerShell of its own into each game's Windows that answers these questions (`Get-ItemProperty`); anything
    else it reports as not possible here, as before.
  - A game that Steam starts with extra arguments is left as it is. Magic Kettle used to close a game started
    from Steam and start it again its own way when its settings weren't known yet; that dropped r2modman's
    arguments, and Muck came back without its mods.
- **A program run with Steam from Downloads is no longer closed as "never showed a window".** HedgeModManager
  opened from Downloads and run with Steam had its window up and working, and after four minutes Magic Kettle
  closed it and said the game didn't start. Programs that share a store's Windows are told apart from the store's
  own by the folder they run from, and a program Magic Kettle starts itself carries its Mac path, which was compared
  with the Windows one and never matched. Both are now compared the same way.
- **Single-file Electron programs open as programs, not installers.** r2modman's one-file download (and other
  "portable" builds made with electron-builder) is packed like an NSIS installer, so Magic Kettle asked where to
  install it and then ran it as an installer. It only unpacks the program to a temporary folder and starts it;
  Magic Kettle now tells it from a real installer and adds it to the library like any other program. It also
  knows such a program is Electron from the start, so the first launch no longer waits a minute and a half on an
  empty window before trying another way, and it draws without the GPU: with it, r2modman's title bar was a
  see-through strip over whatever was behind the window. Since it draws without the GPU, there is no graphics to
  look for either: it starts at once, without the first-launch screen, and with Steam in the graphics Steam
  already runs in, rather than restarting Steam for each one tried. Its window is looked for in the process it
  unpacks, so it is no longer taken for a program that never opened one.

- **.NET programs packed into a single exe get their .NET by themselves.** HedgeModManager 8 is one: the
  `runtimeconfig.json` that says which .NET a program needs sits inside its exe, not beside it, so Magic Kettle saw
  no need and the program stopped on "You must install .NET Desktop Runtime to run this application". Magic Kettle
  now reads it from inside the exe and installs Microsoft's .NET before the first start, as for any other .NET
  program.
- **Mod managers get the Microsoft runtimes they need in Steam's Windows too.** Programs running with a store
  were skipped, because the store's own games bring what they need. A mod manager doesn't, so it now gets .NET or
  Visual C++ installed in the store's Windows, without closing the store and without changing its Windows version.

- **Mod managers have real covers.** r2modman, Gale, HedgeModManager, the Nexus Mods app, SA Mod Manager,
  Sonic Mania's mod manager and Vortex used to show only the small icon from their exe on their card. Each now gets an
  upright cover in its colours with its name, and its own logo where its license allows. Where it doesn't (SA Mod
  Manager's shows Sonic, who is Sega's, and Sonic Mania's has no license), the cover is a background and the icon
  from your own copy of the program is drawn on it. The covers come from Magic Kettle's game settings repository (MagicKettle-Games), like the settings for
  particular games, so more programs can get one without a new app version. A cover is downloaded once when the
  card first shows, checked against the fingerprint the list gives it, and kept. A cover you chose yourself still
  comes first. Vortex uses the icon from your own exe on an amber cover with its name.

- **An installer's window opens in front.** Magic Kettle was the active app when you clicked "Install", and the
  installer's window came up behind it: Vortex's sat under "The installer's window is open" until you found it.
  Each window an installer opens is now brought to the front once, when it first shows.
- **The install window no longer calls every program a game.** It says "Install folder", "the installer" and "Magic
  Kettle will start …", since mod managers such as Vortex or Gale are installed the same way. A mod manager's first
  launch says "program" too: "This program was made for Windows", "Installing components this program needs".

- **Open and Save boxes show your home folder and your external disks, not your Mac's root.** Wine's drive `Z:` is
  the whole Mac disk, and its Windows desktop has a "/" item, so Vortex's folder picker opened at the root, where
  a folder you have no access to closed it. Every game's and program's Windows now has `H:` (your home folder)
  and `V:` (your external disks, without the startup disk, which would lead back to the root), and the same two
  as `Home` and `Disks` in the Windows user folder. `Z:` and "/" are hidden; `Z:` still works for paths that
  need it. Also in installers' "Browse…" boxes.
  - A program in your home folder now sees its own path as `H:\…` rather than `Z:\Users\<you>\…`; its old
    `Z:` paths keep working. Magic Kettle names paths the way Wine does, by the closest drive, so it still finds
    the program's windows.
  - A program that opens its box at a path on `Z:` can still go up to the root from there; it no longer starts
    there.

- **Deleting from disk a game that sits in Downloads takes only its program, not your Downloads.** A game or
  program opened straight from Downloads, the Desktop or the top of a disk had that whole folder as its "game
  folder", and "Delete… › From disk" would have moved all of it to the Trash. Now only the exe goes there, and the
  delete window says so and shows its size, not the size of Downloads.
- **Opening the same exe from Downloads again finds its card.** Magic Kettle doesn't write its small marker file
  into shared folders, so each double-click on a program there added a new card, which looked for its launch
  settings all over again. It is now found by its path. A duplicate card made by an earlier version can be removed
  with "Delete… › Only from Magic Kettle".

- **Installer helpers are allowed to finish.** Unknown worker processes are no longer closed after three seconds;
  only recognized mod managers started by an installer are closed automatically. Other programs may need to be
  closed manually before installation finishes.
- **Mod managers only use stores they support.** SA Mod Manager no longer runs with Epic when Steam is absent.

- **Concurrent preparations keep the first completed Windows template.** Publishing is locked across app and CLI
  processes, so another preparation cannot delete a template that just finished.
- **Installer completion recognizes programs started by their Mac paths too.** Automatically launched mod managers
  no longer keep installation waiting solely because their process uses a Mac path.

## What to watch for

- A game or program opened from your home folder (Downloads, Desktop) now runs from `H:\…` instead of
  `Z:\Users\<you>\…`. A game that saved its own full path and refuses to start, or a launch that says a program
  never showed its window although it did, is worth a report.

- A mod manager's card shows its icon until its cover is downloaded, the first time the library shows it with a
  connection. If a card stays on the icon, or shows a cover that belongs to another program, that is worth a report.
- Installing .NET or Visual C++ for a mod manager happens while Steam keeps running in the same Windows. If
  Steam misbehaves right after a mod manager's first start, that is worth a report.
- A game that ships its own `winhttp.dll`, `version.dll` or `dinput8.dll` for another reason now loads that copy
  too. If a game that worked in 1.0.8 stops starting, that is the first thing to report.
- A program that asks PowerShell for anything other than a registry value still gets nothing, now with a short
  error instead of silence. If a launcher or mod manager reports that PowerShell failed, that is worth a report.
